## 6. 判断に迷った箇所

1. **`<pre>` 内の日本語コメント 2 件**。`-- 壊れている増分境界`（§2(a)）と `-- 残りのマイルストーン date_key・FK・current_stage は 02 回の定義どおり`（§5(b)）。禁止語「壊れ」と資料参照「02 回」が残るが、規約 §4 が SQL コメントを検証対象から除外し、ブリーフが「SQL の変更」を禁止しているため未変更。読者から見える位置なので、コメントのみの変更許可が出れば「誤りのある増分境界」「DM02『ファクトの3型とファクトレス』の定義どおり」に直せる。
2. **図（SVG）の語**。図中に「前回最大値」「毎回置換」があるが数としての「回」で禁止語ではなく、「as-of join」等も含まれていない。ブリーフの指示どおり未変更でよいと判断した。
3. **`{{ audit_key() }}` の説明の補足**。「10回で定義するマクロ」だけでは何を返すか分からないため、`dim_audit` の行のキーを返す旨を 1 文足した。`canon/domain.md` §4 の「全ファクトは `audit_key` を持つ」「`dim_audit` は監査ディメンション」に基づく記述で、新しい設計判断は加えていない。
4. **「ルックバック」をカタカナのまま残すか**。dbt の `lookback` 設定名と対応し本文で 12 回使う中心語なので、翻訳せず初出注釈（「毎回さかのぼって作り直す日数の範囲」）にとどめた。
5. **`AG02` の肩書き**。`canon/domain.md` §5 は `A02` / `AG02` を「ワークリンク（standard）/ 担当 鈴木」とまとめて書いているが、`S002` の記載（`AG01`(agent)）から `AG02` は担当者（agent）側と判断し、冒頭枠では「転職エージェント「ワークリンク」（`standard`）の担当者」とした。氏名（鈴木）は本文で使わないので省いた。
