## 5. 判断に迷った箇所

1. **`<div class="aside kimball">`（Manifesto 1997）内の「既存クエリを壊さない」**
   原典の "gracefully extensible … without breaking existing queries" の訳として置かれており、規約 §3 の「引用文は変えない」に該当すると判断して残した。機械チェック対象は `壊れ` なので 0 件は満たす。地の文に降ろしたい場合は「既存のクエリを無効にしない」が候補。

2. **一覧表・段階表の番号列を `DM00`〜`DM10` にした**
   指示は「表中の参照は『DM01 粒度を宣言する』の形に」。両表とも番号列とタイトル列が分かれているため、列を削らずヘッダを `#`→`資料`、`回`→`資料` に変え、値に `DM` 接頭辞を付けて横に読むと「DM01 粒度を宣言する」になる形にした。

3. **DM07 の題名 `star か One Big Table か` と DM08 の `コンフォームドとドリルアクロス`**
   他資料の題名そのものなので訳さずに残し、地の文の初出側にだけ日本語の説明を付けた（「星形スキーマ（star）に分けるか結合済みの1枚（One Big Table）にするか」「横断集計（ドリルアクロス）」）。

4. **冒頭枠の「収益源」の数**
   最初 3 系統と書いたが §2 の本文が「収益源が4種類」なので、`クチコミの閲覧権限 / 求人の掲載プラン月額 / スカウト枠の契約 / 入社時の成果報酬` の 4 種類に揃えた（本文側の数値は不変）。

5. **`S001` の説明から求人 `J001` を省いた**
   `J001` は本文に一度も出ないため、ID 表に載せると「本文に出る ID」以外を増やすことになる。`S001` の事実は「`C001`（企業として送信）→ `M001`、06-20 送信 / 06-21 開封 / 06-22 返信」に留めた。
