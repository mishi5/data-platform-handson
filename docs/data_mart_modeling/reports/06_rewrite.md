## 6. 判断に迷った箇所

1. **SVG 内の「畳まれる」2 箇所**（`<desc>` と図中の注記）。規約 §4 の `grep` は図を除外していないが、本タスクのブリーフが「図は触らない」と明示しているため未変更。本文側は全て「まとめる」に統一したので、図の語だけ揃っていない。揃えるなら図テキストのみの変更許可が要る。
2. **SQL コメント内の禁止語・資料参照**（`-- 壊れたら weighted report が静かにずれる`、`-- 05回の snapshot から受け取る`、`-- 05回の dim_member をそのまま読む` / `版の畳み込み`、`-- 03回の結論` / `-- 03回の判断` の計 6 箇所）。規約 §4 が明示的に除外し、禁止事項が「SQL の変更」なので手を付けていない。DM03/DM05 の書き直し report も同じ扱い。読者から見える位置ではあるので、コメントのみの変更許可が出れば `DM03『ディメンションの設計』` / `DM05『履歴を持つ：SCD とスナップショット』` に直せる。
3. **`supertype` の訳語**。`canon/domain.md` が `dim_scout_sender` を「異種ディメンション（supertype）」と呼んでいるため、これを固定訳として採用した。ただし §3 の技法表では Kimball の技法名「supertype / subtype スキーマ」でもあるので、その行だけ英語を括弧で残している。
4. **`impact` / `weighted` の日本語化と SQL 列名の不一致**。本文は「重みなし集計」「重み付き集計」に統一したが、SQL の列名は `scout_count_impact` / `scout_count_weighted` のまま（SQL 変更禁止）。初出で英語を併記して橋渡ししている。
5. **`heterogeneous products`**（参照文献）。DWT ch.10 の節見出しそのものなので英語を残し、「＝異種の製品」と訳を添えるに留めた。
6. **職種コード（`ENG-DATA` 等）を冒頭枠に入れるか**。規約 §4 の ID 正規表現では拾われないが、§2(b) の失敗形が「`ENG-DATA` が level2 で終端する」ことに全面的に依存するため、ID 表とは別の段落として枠内に入れた。
