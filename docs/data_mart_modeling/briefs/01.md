# 01 ビジネスプロセスと粒度を宣言する

- ファイル: `html/01_grain.html`／タイトル: `粒度を宣言する — データマート設計 01`
- 参照: DWT ch.2–3（4ステップ、粒度）; Grain; Matrix; DT#3 #77 #179／再解釈: Reis（概念→論理）

## 中心の判断
「このファクトの1行は何を意味するか」を一文で宣言できるか。宣言→ディメンション→ファクトの順序を崩さない。**粒度が混ざった表は必ず二重計上する**。

## 必須内容
- §2 壊れ方: (a) `fct_review` に「クチコミ」と「審査イベント」を混ぜた表（1行が投稿でも遷移でもある）で `review_count` が膨らむ例を `R001` の 3 遷移で示す (b) `fct_scout` と `fct_scout_funnel` を1表にして「送信日で集計したい」と「返信日で集計したい」が衝突する例 (c) `fct_selection_event`（原子）を作らず `fct_application_pipeline`（サマリー）だけを作った場合に答えられなくなる問い（DT#77）
- §3 原典: 4ステップ、原子粒度の原則、「粒度は最も原子的な水準で宣言し、集約は後から」、バスマトリクス（プロセス × コンフォームドディメンション）。domain.md §3 の**バスマトリクスを完全版で載せる**（この回が正本）
- §5 実装: dbt で粒度を**テストとして固定する**。`schema.yml` の `dbt_utils.unique_combination_of_columns`（`fct_job_posting_daily` は `snapshot_date_key` + `job_posting_id`、`fct_review` は `review_id`）と、`description` に粒度宣言の一文を書く規約。`fct_selection_event` の SELECT（`selection_events` → 1行=1遷移）を書く
- §6 判断基準の表: 「答えたい問い → 必要な粒度 → 表の型」を CareerVoice の問い（domain.md §1）ごとに
- §7 演習: (a) `fct_page_view` の粒度を「セッション」にすべきか「ページ表示」にすべきか。答えたい問いから判断させる (b) `contracts` から `fct_contract_monthly` を作る時の粒度宣言を一文で書き、`K001` が 2026-01〜09 で何行になるか答える (c) バスマトリクスに「クチコミへの『参考になった』投票」プロセスを1行足す（ディメンション列の ✓ を判断）
