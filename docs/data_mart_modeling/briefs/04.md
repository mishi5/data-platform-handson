# 04 加法性と派生指標

- ファイル: `html/04_additivity.html`／タイトル: `加法性と派生指標 — データマート設計 04`
- 参照: DWT ch.1, ch.4（加法・半加法・非加法）; DT#77／再解釈: MetricFlow（比率 metric）

## 中心の判断
メジャーは再集約できるか。**率・平均・ユニーク数はマートに持たず、分子・分母・和・件数を持つ**。半加法（残高・在庫）は「どの軸で足せないか」を宣言する。

## 必須内容
- §1 3分類の表（加法 / 半加法 / 非加法）と CareerVoice のメジャー分類（`review_count` 加法、`score_*` 非加法、`scouts_remaining` 半加法=時間で足せない、`fee_rate` 非加法、`avg_overall_score` は持たない）
- §2 壊れ方: (a) **平均の平均**: `agg_company_rating_daily` に `avg_overall_score` を持って月次に平均し直す。`C002` の 3 日分（件数 1, 1, 10）で数値を実際に計算して示す (b) `fct_contract_monthly.scouts_remaining` を 1〜3 月で SUM して「残枠 600」と出る (c) `COUNT(DISTINCT member_id)` を日次で持って週次に足す
- §3 原典: 加法性の定義、半加法メジャーの「期末値・平均残高」の扱い、非加法は「分子分母を分けて持つ」、パーセンタイルは再集約不可
- §4 再解釈: MetricFlow / Semantic Layer で `ratio` metric として分子分母を定義すると BI 側で正しく再集約される、という位置づけ。`metrics.yml` の例（`reply_rate = replied / sent`）
- §5 実装: `agg_company_rating_daily`（`SUM(score_*)`, `COUNT(*)`）と、そこから月次・企業グループ（`br_company_hierarchy` 経由で `C001`+`C003`）を再集約する SQL。半加法 `scouts_remaining` を「月末値」で出す `QUALIFY ROW_NUMBER()`。`APPROX_QUANTILES` を持つなら原子ファクトから直接、の指針
- §6 判断基準: 「メジャー → 分類 → マートに持つ形 → BI で計算する形」の表
- §7 演習: (a) `fct_review.overall_score` の「企業別・年別の中央値」を出すために何を持つか (b) `fct_job_posting_daily.is_open` を月で SUM したら何を意味するか（延べ掲載日数）と、「月末時点の掲載数」の出し方 (c) 返信率を「スカウト送信主体別」に見る時、分子分母をどの粒度で持つか

## 図（1枚）
**平均の平均 vs 和と件数**（比較図型）: 左パネル=「日次 avg を持って月次で AVG」、右パネル=「日次 sum/count を持って月次で SUM/SUM」。同じ 3 日分の数値（§2 の例）を両パネルに置き、結果の違いだけ accent。ノード ≤9。
