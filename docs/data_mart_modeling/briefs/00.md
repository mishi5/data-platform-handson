# 00 題材と簡易データモデル

- ファイル: `html/00_domain.html`／タイトル: `題材と簡易データモデル — データマート設計 00`
- 参照: DWT ch.1（4ステップ設計）, ch.18（設計プロセス）; 10 Rules; Manifesto／再解釈: Reis（概念/論理/物理の階層）, Hightouch 1

## 目的
シリーズ全体の入口。題材（CareerVoice）を定義し、以降の回が同じテーブル・同じ ID で語れる土台を作る。
**このシリーズが DMBOK シリーズ（総論）と違い「マートを作る時の判断」だけを扱う**ことを冒頭で1段落宣言する。

## 節構成（この回だけ特例）
1. このシリーズが扱うこと … 位置づけ、全11回の一覧表（回番号・タイトル・中心の判断を1行ずつ。`canon/plan.md` の一覧をそのまま使う）
2. 題材: CareerVoice … サービス概要の表（domain.md §1）、分析側が答えたい問い
3. ソースシステムの簡易モデル … domain.md §2 の表を**そのまま**転載（列を省略しない）。OLTP としての設計意図（正規化されている、状態列で遷移を持つ、論理削除）を短く
4. ビジネスプロセスの棚卸し … domain.md §3 のプロセス一覧。**「部門ではなくプロセス」（DT#3）** を原則として置く
5. 概念→論理→物理 … Reis の階層と DWT の4ステップ（プロセス選択→粒度宣言→ディメンション→ファクト）を対応表に。このシリーズの各回がどの段階に属するかを表で
6. 判断基準 … 「このシリーズで固定した設計判断」= domain.md §6 の表を転載し、各行の「扱う回」を示す
7. 演習 … (a) 自分の担当システムで「ビジネスプロセス」を5つ挙げ、部門名になっていないか確認する形式の問い（解答例は CareerVoice で示す）(b) `reviews.status` の状態遷移を列挙し、どれがファクトになりどれがディメンションになるかを分類
8. 参考: 手元の基盤 … dbt_logs_analysis は「アクセスログ」という**データソース起点**でマートを作っていて、プロセス起点になっていない（`mart_url_performance` はプロセス名ではなくテーブル名）。news_pipeline はプロセス（収集・要約・通知・お気に入り）ごとにテーブルがある点で自然にプロセス起点、という対比

## 図（1枚）
**OLTP 簡易 ER 図**（アーキテクチャ図型・ノード ≤9）: `members`, `companies`, `reviews`, `job_postings`, `scouts`, `applications`, `selection_events`, `contracts`, `agents` の 9 ノード。矢印は FK の向き（子→親）だけ。`page_views` と参照マスタは省いて注記に落とす。ゾーンは「会員側 / 企業側 / エージェント側」の3つまで。

- domain.md §2 の全テーブル表（列を落とさない）
- バスマトリクス（domain.md §3）を予告として載せる（詳細は 01 回）
