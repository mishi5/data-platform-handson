# 05 履歴を持つ：SCD とスナップショット

- ファイル: `html/05_scd.html`／タイトル: `履歴を持つ：SCD とスナップショット — データマート設計 05`
- 参照: DWT ch.5; SCD 1–2; DT#15 #152／再解釈: FDE（ディメンションの日次スナップショット）, SCD2 harmful, dbt snapshots

## 中心の判断
属性の変化をどう残すか。Type 0/1/2/3/4/6/7 の選択と、**イベント時点の属性で結合する（point-in-time / as-of join）** の実装。SCD2 と日次スナップショットのどちらを採るか。

## 必須内容
- §1 Type 0〜7 の表（定義 / 履歴 / 行の増え方 / CareerVoice での適用: `dim_company.name`=1、`employee_size_band`=2、`dim_member_profile_mini` 経由=4（ミニディメンション）、`dim_company` 全体=6 相当）
- §2 壊れ方: (a) `dim_company` を Type1 にして「`C002` が `50_299` だった頃のクチコミ平均」が出せなくなる (b) `fct_scout` を**現在の** `member_key` で結んで、`M001` の 6/20 のスカウトが `active`（6/15 以降）ではなく最新のプロフィール（8/1 入社後）に紐づく (c) `valid_to` を NULL にして `BETWEEN` が外れる（`9999-12-31` を入れる）
- §3 原典: Type2 の `valid_from/valid_to/is_current`、Type6、DT#15 の組合せ。「ファクトはロード時点でサロゲートキーを解決する」原則
- §4 再解釈: FDE の「毎日ディメンション全体をパーティションにスナップショットする」方式。利点（冪等・単純・as-of が `WHERE snapshot_date = event_date` で済む）と欠点（行数 = 会員数 × 日数、属性変化の瞬間が日単位に丸まる）。Zach Wilson の「SCD2 は運用が重い」論。**判断: 会員（数百万 × 日）はスナップショット、企業（数万）は SCD2**、を根拠付きで
- §5 実装: (a) dbt snapshot（`strategy='timestamp'`, `updated_at`）で `snap_companies` → `dim_company` を組む SQL（`dbt_valid_from/to` → `valid_from/valid_to`、`COALESCE(valid_to, '9999-12-31')`）(b) **as-of join**: `fct_scout` を作る時 `scouts.sent_at BETWEEN dim_member.valid_from AND valid_to` で `member_key` を解決する SQL。`S001`（6/20）が 6/15 版に当たることを表で (c) 日次スナップショット版: `dim_member_daily`（`PARTITION BY snapshot_date`）と `WHERE snapshot_date = DATE(sent_at)` の結合 (d) 「現在値で見たい」時は `company_id` で `is_current` 版に再結合
- §6 判断基準: 「行数 × 変化頻度 × 必要な時間精度 → Type / スナップショット」の表
- §7 演習: (a) `dim_agent` で担当者が `A01`→`A02` に移籍した時、過去の `fct_placement` はどちらのエージェンシーに計上されるべきか（Type2 なら移籍前、Type1 なら移籍後。業務ルールで決める） (b) `M001` の 6/15 と 8/1 の変化で `dim_member` は何行になるか。各行の `valid_from/to` (c) `dim_company.name` の社名変更を Type1 にすると困る分析はあるか

## 図（1枚）
**as-of join の概念図**: 横軸=時間。上段に `dim_member` の `M001` の3つの版（〜6/14、6/15〜7/31、8/1〜）を帯で、下段にイベント `R001`(3/10)、`S001`(6/20)、`P001`(6/23) を点で置き、各イベントが真上のどの版に当たるかを縦の矢印で。accent は 6/15〜7/31 の版とそこに落ちる2イベント。ノード ≤9。
