# スコアロジック改善（キーワード依存を減らしDE価値で採点）設計書

作成日: 2026-06-08

## 目的

importance_score の採点を、現状の「keyword 一致度の自己申告」から「**データエンジニアにとって読む価値があるか**の総合判断（keyword は補助ヒント）」に変える。スコアのアンカー（目安レンジ）を与えて Haiku のスコアのブレを抑える。`SCORING_VERSION` を上げ、既存 summaries は `/recalculate` で再採点する。

関連: [2026-06-07-importance-score-recalculation-design.md](2026-06-07-importance-score-recalculation-design.md)（本改善が使う再計算基盤）

## 方針（確定事項）

| 項目 | 決定 |
|------|------|
| 主軸 | 「データエンジニアにとって読む価値があるか」の総合判断 |
| keyword の役割 | 興味分野のヒント（該当すれば加点）。keyword に無くても価値があれば相応に高く |
| 高スコア軸 | 実務で使える知見 / 技術的な深さ・考察 / 大規模・本番事例 |
| 低スコア軸 | 宣伝・PR・製品紹介 / 中身が薄い・短い |
| アンカー | 入れる（0.8〜 / 0.5前後 / 0.3以下 の目安） |
| 版 | `SCORING_VERSION` を 1 → 2 |
| 既存行 | デプロイ後 `/recalculate` を繰り返して版2へ再採点 |
| 閾値 | `general/importance_threshold` は 0.65 のまま（変更しない） |

新規性・時事性は高スコア軸に含めない（中身重視）。入門・非技術は明示的な減点軸にしない。

## 変更内容

### summarizer.py

`_build_scoring_criteria(keywords: list[str]) -> str` を以下の内容を返すよう書き換える（keyword の列挙と「キーワード未設定」表現は維持し、既存テストを壊さない）:

```
importance_score は「データエンジニアにとって読む価値があるか」を総合的に判断して付ける。

高くすべき記事（価値が高い）：
- 実務で使える具体的な知見（設計・運用ノウハウ、how-to、トラブル対応）
- 技術的な深さ・考察（アーキテクチャ議論、仕組みの深掘り、トレードオフ分析）
- 大規模・本番環境の実例（実サービスの事例、失敗談やスケールの教訓）

低くすべき記事（価値が低い）：
- 宣伝・PR・製品の単なる紹介（マーケティング目的）
- 中身が薄い・短い（具体性がなく表面的）

次のキーワードは特に関心の高いトピックのヒント。該当すれば加点するが、キーワードに無くても上記の価値があれば相応に高くする：
<keywords を列挙 / 未設定時は「（キーワード未設定のため、データエンジニアリング全般を対象とする）」>

スコアの目安：
- 0.8〜1.0: 実務に直接役立つ深い技術記事、本番事例の濃い知見
- 0.5前後: 有用だが一般的、または部分的に価値がある
- 0.3以下: 宣伝・PR、中身が薄い、データエンジニアにほぼ無関係
```

- keyword あり: 各語を `  - {kw}` で列挙。
- keyword なし: `  （キーワード未設定のため、データエンジニアリング全般を対象とする）`。
- `SCORING_VERSION = 1` を `SCORING_VERSION = 2` に変更。
- `_build_system_prompt` / `_build_score_only_prompt` / `summarize_article` / `score_article` は変更不要（criteria を共有しているため自動的に新基準になる）。

## 影響

- **collect（新着）**: 新基準で採点され、`scoring_version=2` で保存される。
- **recalculate（既存）**: `/recalculate` が `scoring_version IS NULL OR < 2` の行（現状 NULL 609件 + v1 50件 = 659件）を版2で再採点。`recalculate_limit`（既定50）ずつなので十数回叩いて消化。
- **閾値0.65 + アンカー**: 「0.5前後＝一般的」記事は閾値未満で summaries に残らない（深い記事・濃い事例のみ通過）。中身重視方針と整合。通知が減りすぎたら閾値を下げて調整可能。

## テスト

- `test_summarizer.py` の既存テスト（`_build_scoring_criteria` が keywords を含む / 「キーワード未設定」を含む、`_build_system_prompt` 同様）が引き続き通ること。
- 追加: `_build_scoring_criteria` の出力に新基準の語（例: 「読む価値」「スコアの目安」）が含まれることを軽く検証。
- `score_article` / `summarize_article` の既存テスト（モックで JSON を返す）は基準文変更の影響を受けず通る。

## ドキュメント

- CLAUDE.md / README の運用記述は既存の「ロジック変更→SCORING_VERSION +1→デプロイ→/recalculate」で足りるため、追加変更は不要。必要なら scoring の主軸が「DE価値（keyword は補助）」である旨を一言追記する程度。

## 非対象（YAGNI）

- 多軸スコア（軸ごとの数値化・重み付け合成）
- 判定モデルの変更（Haiku のまま）
- 本文切り詰め長（3000字）の変更
- 閾値の変更（0.65 維持）
- A/Bや版間のスコア履歴保持（上書きのみ）
